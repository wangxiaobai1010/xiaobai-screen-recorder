# P2.5 正式长测控制入口

## 目标与非目标

`XbPreview.LongRun` 是独立的 x64 Console 测试入口，用于重复执行 P2.5 正式 Preview 与 RecordingController 长时闭环，并输出可复核的 JSONL、summary 和 MP4 证据。

它不是第二套录制控制器：入口通过仅授予 `XbPreview.LongRun` 的 `InternalsVisibleTo`，直接实例化正式 `PreviewLifecycleController`、`RecordingController`、`NativePreviewSession` 和 `ManagedRecordingSnapshot`。它不复制录制状态机，不直接调用 Native Recording Export，不管理 Encoder、帧或时间戳，也不进入正式 Host UI。

本工具不改变 Native ABI、Encoder、FrameTap、OutputCanvas、编码参数或产品录制语义。它不实现 P2.6、安全保存、音频、暂停或 30/60 FPS。

## 正式调用关系

一次运行固定执行：

1. 在单一 STA 消息循环中创建测试 Preview 窗口和稳定 HWND。
2. `PreviewLifecycleController.InitializeAsync` → 设置全屏 `SessionGeometry` → Resize → `StartAsync`，确认状态为 `Previewing`。
3. 从该生命周期取得唯一 `RecordingController`，调用 `StartAsync` 并等待真实 `Recording`。
4. 按采样周期调用同一 Controller 的 `RefreshSnapshot`。
5. 达到目标墙钟时长后调用 `StopAsync`；取消、Ctrl+C 或异常则调用 `StopForCloseAsync`。
6. Stop 返回后，再从正式 Controller 独立调用 `RefreshSnapshot`，等待 `Completed` 或 `Failed`。只有这次独立终态读取可进入最终 summary。
7. 终态 Snapshot 以 `sampleType=terminal` 写入 JSONL。
8. 调用 `PreviewLifecycleController.CloseAsync`，完成 Preview 关闭和资源归还。

任何取消都禁止 force kill。自动取消参数从进入 Recording 后开始计时，不从进程启动时计时。

## 命令行与目录

必填参数：

- `--duration-seconds <正整数>`：进入 Recording 后的目标墙钟时长。

可选参数：

- `--sample-interval-ms <正整数>`：默认 1000，最大 60000。
- `--output-directory <路径>`：默认 `artifacts\p2.5-long-run`。
- `--run-id <标识>`：1–64 个 ASCII 字母、数字、点、下划线或连字符；首字符必须是字母或数字。
- `--summary-json <路径>`：summary 最终路径。
- `--snapshots-jsonl <路径>`：Snapshot JSONL 最终路径。
- `--cancel-after-seconds <正整数>`：仅用于短取消自检，必须小于 duration。
- `--self-test-arguments`：参数解析测试。
- `--self-test-evidence-gates`：证据门禁与故障测试。
- `--self-test-final-hardening`：真实 Git/模块采集、JSON schema、证据发布故障、Close 与结束原因竞态测试。

所有路径在解析时转换为绝对路径并写入 summary。工具拒绝零、负数、数值溢出、未知参数、重复参数、非法 run-id、相同证据路径、现有 run root、现有 summary/JSONL 和 Native ABI 无法容纳的过长路径。

每个 `<output-directory>\<run-id>` 是独立目录，使用 `FileMode.CreateNew`，不得覆盖。仓库内部证据路径必须被 Git 忽略；仓库外的合法绝对路径允许使用。

为保持 Native ABI 不变，diagnostic directory 放在 run root 下四级位置，沿用 Native `ArtifactsRoot` 规则，使正式 MP4 写入：

```text
<run-root>\p2.5a-recordings\<session-guid>.mp4
```

工具不移动、复制、重命名或猜测 MP4。

## 实际加载模块核验

核验发生在 Preview 已进入 `Previewing`、Native DLL 已真实加载之后：

- `XbPreview.LongRun.exe`：来自当前进程 `MainModule.FileName`。
- `XbPreview.Host.dll`：来自已加载 `PreviewLifecycleController` 的 `Assembly.Location`。
- `XbPreview.Native.dll`：来自当前进程 `Process.Modules`。

每项记录实际加载路径、文件大小、`LastWriteTimeUtc`、SHA-256、加载事实来源，以及是否位于仓库精确的 `artifacts\bin\Release\x64`。缺失、路径不符、哈希读取失败或目录不符均为 BLOCKED。未启动的 `XbPreview.Host.exe` 不作为实际加载模块记录。

## Git 可复现性

开始和结束分别记录：

- HEAD commit；
- 当前分支；
- 完整 `git status --porcelain=v1 --untracked-files=all` 原文；
- `Clean`。

结束时逐字节比较 HEAD、分支和 status。正式 PASS 或 CANCELED-SAFELY 必须同时满足：起止工作区均干净、HEAD 未变、分支未变、status 完全一致，并且仓库内证据路径受 `.gitignore` 保护。任一条件失败均为 BLOCKED。

因此最终 15 秒和取消自检只能在功能提交完成、`git status --short` 为空后执行。

## Snapshot JSONL

每个样本只来自正式 Managed Snapshot，记录：UTC、`sampleType`、墙钟时长、RecordingState、Session GUID、Native PTS、OutputPath、FramesSubmitted、ActiveEncoder、Finalize 字段、OutputSuccess、主失败、输出清理结果、ResidualOutstanding、Preview 状态和当前 LongRun 进程资源。

停止后独立读取的终态 Snapshot 必须是唯一且最后的 `sampleType=terminal` 样本。JSONL 先写同目录、名称含 `incomplete` 的临时文件；关闭时执行：

1. Flush；
2. 文件流 `Flush(true)`；
3. 关闭 writer；
4. 确认临时文件存在且非空；
5. 每行反序列化为正式 `LongRunSample`，逐字段验证类型、合法状态、Session、PTS、Finalize、Output 与资源语义；
6. 行数必须与采样统计一致，Session 必须与本次运行一致；
7. terminal 样本必须恰好为 1、位于最后，并与内存中的独立终态 Snapshot 逐字段一致；
8. 无覆盖原子移动到最终 JSONL 路径并再次完整读取验证。

任一步失败不得 PASS。

## 资源统计

资源对象是当前 `XbPreview.LongRun` 进程，因为正式 Preview 和 Controller 在该进程内运行。每次读取前调用 `Process.Refresh`。

至少采集：

- baseline：Preview 启动前；
- running：所有 Recording 与 terminal 样本；
- final：Stop、Finalize 和 Preview Close 后。

WorkingSet、PrivateMemorySize、HandleCount、ThreadCount 的 max 从三个阶段全部可用样本统一计算，不忽略 start 或 end。读取失败时各字段写 null 并记录错误，不伪造为 0。Windows 进程资源与 Native `ResidualOutstanding` 分开报告。

结束时还会扫描除当前 LongRun 外的 Host、Managed.Tests、Native.Tests 和其他 LongRun 进程；发现残留即 BLOCKED。

## PASS 与 CANCELED-SAFELY 矩阵

普通 PASS 必须满足全部 Required Gate：

| Gate | PASS 条件 |
|---|---|
| target-wall-duration | 实际墙钟时长不小于 duration |
| session-guid | 非空且可解析为非零 GUID |
| session-consistent-across-samples | 全部样本属于同一非空 Session |
| final-native-pts-positive | 最终 Native PTS 大于 0 |
| pts-monotonic | 全部采样 PTS 不下降 |
| state-sequence-legal | 每个相邻状态转换合法 |
| terminal-completed | 独立终态 Snapshot 为 Completed |
| terminal-snapshot-reread | Stop 后通过 Controller 独立重读 |
| finalize-attempted | FinalizeAttempted=1 |
| finalize-count-one | FinalizeCount=1 |
| finalize-hresult-success | FinalizeHResult 成功 |
| output-success | OutputSuccess=1 |
| source-reader-validation | Native SourceReaderValidation=PASS |
| output-path-absolute-mp4 | 完整绝对 `.mp4` 路径 |
| mp4-exists-nonzero | 文件存在且大于 0 bytes |
| snapshots-jsonl | 已关闭、落盘、逐行可解析、计数一致 |
| native-residual-zero | ResidualOutstanding=0 |
| native-encoder-inactive | ActiveEncoder=0 |
| preview-closed | Preview 正常关闭 |
| related-processes-zero | 除当前 LongRun 外无相关残留进程 |
| loaded-modules | 三个实际加载模块及指纹正确 |
| git-reproducibility | 起止 clean 且 HEAD/分支/status 未变 |
| process-metrics-complete | baseline/running/final 均可读取 |

取消结果只能是 `CANCELED-SAFELY` 或 `BLOCKED`，绝不写成普通 PASS。CANCELED-SAFELY 不要求达到目标 duration，但其余所有 Required Gate 与普通 PASS 完全相同。任何 Finalize、MP4、SourceReader、JSONL、summary、资源、模块、Git 或关闭事实失败，取消结果必须为 BLOCKED。

结束分类由 `XbPreview.LongRun` 生产路径和负向测试共用的 `LongRunTerminationCoordinator` 负责。`DurationReached`、`CancellationRequested`、`RuntimeFailure` 通过一次 CAS 只有一个可以成为主结束原因；`CancellationObserved`、`DurationTargetReached` 和 `RuntimeFailureObserved` 作为独立单调事实写入 summary。CancellationToken 注册覆盖运行、Stop、终态读取、Preview Close 和 `RunFinalizing`；随后 `Seal()` 注销注册、补读 token 并冻结不可变终止事实，再据此计算 Gate 和发布 summary。Seal 之后到达的控制台信号不属于本次运行的终止竞态。

达到目标时长后，Harness 会先记录 `DurationTargetReached` 并立即 CAS `DurationReached`，然后才发布 `TimedRunCompleted` 阶段并进入 Stop；若取消先赢，后续 Stop、终态读取和 Close 不能把它改回普通 PASS。若 Duration 先赢，之后到达的取消仍会由 `CancellationObserved` 如实记录，不改写已确定的主结束原因，但公开结果只能是 `CANCELED-SAFELY` 或 BLOCKED，不能再输出普通 PASS；此时目标时长 Gate 仍按 Duration 原因保持 Required。任何时刻观察到 RuntimeFailure 都会通过独立标记使最终结果 BLOCKED，即使主原因此前已经锁存。

Preview Close 不能只看 `Disposed`。Harness 会结构化保存 Close 调用是否完成、最终生命周期状态、完整 `LastError`、异常文字，以及关闭前后相关进程事实。只有 `Disposed + LastError 为空 + 无异常 + 关闭后相关进程为零` 才能通过 `preview-closed` Gate。

## Summary 原子发布

正确顺序为：

1. 完成终态、关闭 Preview、采集 Git 结束事实；
2. 关闭、发布并验证 JSONL；
3. 计算全部 Required Gate；
4. 从路径解析、父目录创建开始进入统一不抛出的发布边界；
5. 在 summary 同目录以 `CreateNew` 写名称含 `incomplete` 的临时文件；
6. `Flush(true)`、关闭并反序列化为正式 `LongRunSummary`；
7. 验证完整顶层 schema、结束原因三项事实以及 Verdict/ExitCode 一致性；
8. 从声明路径重新读取正式 JSONL、唯一 terminal、MP4 大小和同 Session 的 SourceReader 诊断，从这些磁盘事实重建状态、PTS、Session、进程最大值和全部 23 个 Gate，并逐项比对 summary 中的 `Required/Passed`；
9. 使用不允许覆盖的原子 `File.Move` 发布到最终路径；
10. 重新打开最终文件，再次进行类型、schema、外部证据、23 项 Gate 和与待发布对象逐字段一致性验证；
11. 只有发布成功后才能一次性打印 PASS/CANCELED-SAFELY 并返回对应退出码。

发布后验证失败时，最终文件会被移到带 `.invalid-*` 后缀的诊断路径。任何写入、刷新、解析、移动或复核失败均只打印 BLOCKED，并返回专用非零退出码；禁止出现 `LONG-RUN-RESULT: PASS; exit=7`。

`--self-test-final-hardening` 的故障接缝只存在于 LongRun 测试基础设施。生产默认始终使用真实文件系统；测试分别真实验证临时 Git dirty、实际加载模块与错误期望目录、JSONL 缺字段/错类型/错 Session/非法 terminal、矛盾的 PASS/终态对象、summary 父目录创建失败、目标已存在，以及 Write、Flush、临时复读、Move 前后异常、最终复读和最终结果输出失败。所有失败都必须无 PASS 输出并返回非零退出码。

取消竞态测试直接使用生产 `LongRunTerminationCoordinator` 的真实 `CancellationToken.Register` 与正式 `NotifyStage`，在 running、Stop、终态读取和 Close 阶段用另一线程触发取消并验证 CAS 赢家；Publisher 的晚取消正测验证的是 Seal 前已观察并冻结的取消事实能够以 `CANCELED-SAFELY` 原子发布，不声称在 Publisher 内再次接收取消。这些是共享协调器的阶段级并发自检，不冒充 Native Encoder/Finalize 集成测试。真实 Preview、Controller、Finalize 与 Close 仍由提交后唯一一次 15 秒正向和 2 秒取消自检证明。

## 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | PASS |
| 2 | 参数或覆盖风险 |
| 3 | Preview 启动失败或前置进程冲突 |
| 4 | Recording Start 失败 |
| 5 | 运行中 Failed 或非法状态 |
| 6 | Stop/Finalize 失败 |
| 7 | 输出或证据验证失败 |
| 8 | 资源残留或 Preview 未关闭 |
| 9 | CANCELED-SAFELY，不是普通 PASS |
| 10 | 未处理异常，仍尽力安全 Stop/Close |
| 11 | Required Evidence Gate 失败 |
| 12 | summary 原子发布失败 |

## 固定命令

以下命令保持不变。每个 run-id 只能使用一次；重跑必须使用新 run-id，禁止删除或覆盖旧证据。

120 秒演练：

```powershell
artifacts\bin\Release\x64\XbPreview.LongRun.exe --duration-seconds 120 --sample-interval-ms 1000 --output-directory artifacts\p2.5-long-run --run-id preflight-120-20260806
```

300 秒演练：

```powershell
artifacts\bin\Release\x64\XbPreview.LongRun.exe --duration-seconds 300 --sample-interval-ms 1000 --output-directory artifacts\p2.5-long-run --run-id preflight-300-20260806
```

3600 秒最终长测：

```powershell
artifacts\bin\Release\x64\XbPreview.LongRun.exe --duration-seconds 3600 --sample-interval-ms 1000 --output-directory artifacts\p2.5-long-run --run-id final-3600-20260806
```

## 禁止事项

- 运行长测期间不得修改工具、源码、脚本、分支或参数后继续沿用同一次结论。
- 不得使用任务管理器、force kill 或直接 Native Stop 代替正式 Controller 收尾。
- 不得在 120/300/3600 秒运行中现场修代码或删除证据。
- Harness ready、15 秒 PASS 或取消安全 PASS 均不代表 60 分钟最终集成门禁已经通过。
