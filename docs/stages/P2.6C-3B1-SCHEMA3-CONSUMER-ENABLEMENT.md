# P2.6C-3b-1 Schema 3 Reader / Validator / Consumer Enablement

## 1. 阶段目标与非目标

本阶段在任何生产 Narrow Reconciler writer 启用之前，先让 Native Manifest
reader、strict validator 和所有历史 Manifest consumer 无歧义地认识 schema 3、
`ReconciledCompleted` 与 reconciliation provenance。

本阶段没有实现 Narrow Reconciler，没有写回任何历史 Session，没有进行启动期
reconciliation，没有修改媒体文件，也没有修改 Native ABI、Managed API、
RecordingSnapshot、UI 或 LongRun。

本阶段的准确状态是：

> Reader Ready != Writer Enabled

## 2. Schema 3 model

常规录制 writer schema 仍为 `2`。新增的只读目标 schema 常量为 `3`，并新增独立
lifecycle state `ReconciledCompleted`。旧 `Created` 至 `Unknown` 枚举值保持原顺序，
没有改变既有 schema 1/2 持久语义。

Schema 3 在 schema 2 事实之上只增加一个 root-level `reconciliation` object；root
字段数量与 reconciliation 内部字段数量均严格校验，不允许缺字段、额外字段或默认补值。

## 3. Reconciliation provenance

冻结合同中的最小 provenance 已逐字段实现：

- `reconciled`
- `kind`
- `sourceRevision`
- `reconciledAtUtc`
- `evidenceKind`
- `originalPublishResultKnown`
- `confirmedFinalPath`

`kind` 只接受 `FinalAtPlannedPathSamePersistentFileV1`；`evidenceKind` 只接受
`MaintenanceLeaseCasHeldFinalIdentityV1`。两者均为 Native 受控 enum，不接受任意
字符串。第一版合法 target 必须保持 `originalPublishResultKnown=false`，且
`confirmedFinalPath` 必须与 `plannedFinalPath` 语义相等。

FILE_ID_INFO 没有在 provenance 中重复持久化；schema 2 已有的 persistent Working
identity 继续是底层对象身份事实。

## 4. Strict validator

Schema 3 只有以下完整组合合法：

- `schemaVersion=3`；
- `state=ReconciledCompleted`；
- `reconciled=true`；
- 两个受控 kind 均为冻结合同值；
- `revision=sourceRevision+1`，并满足 JSON exact-integer 范围；
- `updatedAtUtc` 与 `reconciledAtUtc` 逐字符完全相等；
- `originalPublishResultKnown=false`；
- `confirmedFinalPath=plannedFinalPath`；
- Working 所有权、媒体提交、worker 退出、资源释放、Finalize、Validation 和
  persistent identity 事实均满足原 ReadyToPublish 严格语义；
- `publish.attempted=false`、`publish.published=false`、`publish.hresult=null`；
- `publishedPath` 为空；
- post-publish verification 与 error facts 均未被伪造。

缺 provenance、非法 enum、revision/timestamp/path 关系错误、伪造 publish 事实、
缺 identity、改变 source media facts 等组合均返回 `SemanticInvalid`，并保持调用者
输出对象不变。格式损坏仍为 `MalformedJson`，schema 4 及未来版本仍为
`UnsupportedSchema`。

## 5. Schema 1 / 2 compatibility

- Schema 1 继续使用 22 字段 legacy 模型，不要求 persistent identity，Scanner 仍
  保守 Retain。
- Schema 2 继续使用 24 字段 Native recording 模型；正常 writer 固定写 schema 2。
- Schema 1/2 若携带 reconciliation facts 或 `ReconciledCompleted` 均严格拒绝。
- 原来以 schema 3 作为“future schema”的测试 fixture 已随版本激活改为 schema 4；
  这只是测试版本迁移，不是 validator 放宽。

## 6. ReconciledCompleted 的正式语义

`ReconciledCompleted` 表示 recovery/reconciliation evidence 已证明同一个底层媒体对象
当前安全位于 `PlannedFinalPath`，并将该 persistent fact 表达为 schema 3 target。

它不声称历史 Native `MoveFileExW` 调用结果已知，也不伪造原始 publish success。

## 7. 为什么它不是 Native Completed

P2.6A 的定义保持不变：

> Native Completed := ReadyToPublish && Published

Schema 3 `ReconciledCompleted` 是历史恢复语义，不是 `Completed` 的别名。Native
runtime state、RecordingSnapshot state 和 `Completed` 判断均未修改。

## 8. 为什么它不是 OutputSuccess

`OutputSuccess` 仍只来自当前进程 P2.6A runtime Snapshot 的 Native Completed 事实。
Schema 3 reader 不写 RecordingSnapshot，不把 `publish.published` 补为 true，也不填写
`publishedPath`。因此：

> ReconciledCompleted != Native Completed != OutputSuccess

## 9. ReconciledCompletedConsistent

`SessionInspection` 新增独立分类 `ReconciledCompletedConsistent`，绝不复用
`CompletedConsistent`。只有 strict schema 3 已通过，并且只读 Path Safety 证明 final
是非零 regular file、Working 不存在、当前 final persistent identity 与持久 Working
identity 相同、hard-link count 为 1 时，才产生该分类。

Final 缺失、身份不匹配、类型/路径不安全或 schema 3 语义无效均保守进入 conflict/
Retain。无论 owner 是 active 还是 inactive：

- `deleteAllowed=false`
- `reconciliationAuthorized=false`

## 10. Old consumer 审计

| Consumer | 是否读取历史 Manifest | Schema 3 行为 |
| --- | --- | --- |
| `SessionManifest` parser/validator | 是 | 显式 parse，严格 validation，非法组合 fail closed |
| `SessionInspection` / classification switch | 是 | 独立 `ReconciledCompletedConsistent`，不复用 Completed |
| `ReconciliationEvidenceGuard` | 是 | 仍只接受 strict schema 2 `ReadyToPublish`；schema 3 不会被当作 Guard source |
| `SessionManifestStore` normal Create/Update | 是/写入 | Create 强制 schema 2；既有 state transition 不提供 schema2→3 migration |
| `VideoEncoderConsumer` | 生产 writer，不读取历史 Session | 只增加显式诊断名称；状态赋值仍仅 Created→Completed/Failed，绝不产生 ReconciledCompleted |
| Native Exports / `RecordingSnapshot` | 否 | NOT-A-CONSUMER；ABI 与 runtime state 不变 |
| Managed `RecordingController` / MainForm | 否 | NOT-A-CONSUMER；继续读取 runtime Snapshot |
| LongRun | 否 | NOT-A-CONSUMER；继续验证 runtime Snapshot、PublishedPath 与 OutputSuccess |

全仓 state/Completed/OutputSuccess 搜索未发现 default/fallthrough 将
`ReconciledCompleted` 映射为 Published、Completed 或 OutputSuccess 的路径。

## 11. Managed / Snapshot / LongRun 边界

Snapshot 继续表达当前进程 runtime 事实；Manifest 继续表达跨启动 persistent 事实。
本阶段没有修改 `XbPreviewApi.h`、Exports、P/Invoke、Managed controller、MainForm 或
LongRun。Native API 仍为 `0x00040001`，`XbRecordingSnapshot` 仍为 2856 bytes。

因此 Managed interop 定向回归按影响面跳过；ABI v4 Native 门禁已实际运行并通过。

## 12. 生产 Schema 3 writer 仍禁用的证明

- `CreateManifest` 无条件把 candidate schema 固定为 `SessionManifestSchemaVersion`，即 2。
- `VideoEncoderConsumer` 的正常 lifecycle 不赋值 `ReconciledCompleted`，也不构造
  reconciliation provenance。
- `StateTransitionAllowed` 没有 schema 2 Ready→schema 3 target 的迁移。
- `ReconciliationEvidenceGuard` 只建立证据，不调用 schema 3 writer。
- 新 44 项矩阵中的普通 Create 与完整 Published→Completed fixture 均保持 schema 2，
  持久 JSON 不包含 `reconciliation`。
- P2.6A-3 真实短编码/发布回归通过，未产生 schema 3。

Generic serializer/parser 对 schema 3 的表示能力只服务 reader/fixture 和未来 dedicated
writer；当前没有生产 schema2→schema3 mutation 调用链。

## 15. 已知限制

- 本阶段不写 schema 3，不修改或 reconciliation 任何历史 Manifest。
- 本阶段不实现 startup reconciliation、Managed startup、Recovery UI 或用户决策流。
- `ReconciledCompletedConsistent` 是只读分类，不是 mutation authorization。
- 本阶段不移动、删除、复制、修复或清理媒体。
- P2.6B 远程同步仍为 `REMOTE-SYNC-PENDING`，本阶段没有访问 GitHub。

## 16. P2.6C-3b-2 所需接口

下一阶段只能在现有冻结 Guard、maintenance lifetime lease、held final handle、Working
absence double-check、expected-revision CAS 和 operation-time revalidation 之上，实现
dedicated、窄化的 schema 2 ReadyToPublish→schema 3 ReconciledCompleted candidate builder
与 mutation validator。

它必须一次捕获 `nowUtc`，保持所有 source facts，写入本阶段的严格 provenance，处理
operation-time AlreadyReconciled/semantic-equivalent loser，并继续保证媒体零 mutation。
本阶段没有开始这些工作。

## 17. 阶段结论

Schema 3 reader、strict validator 和历史 Manifest consumer 已按冻结合同 reader-first
启用；非法组合 fail closed，schema 1/2 不退化，Scanner 不获得 mutation 权限，生产
writer 仍为 schema 2。

结论：`P2.6C-3B1-SCHEMA3-CONSUMERS-READY`。
