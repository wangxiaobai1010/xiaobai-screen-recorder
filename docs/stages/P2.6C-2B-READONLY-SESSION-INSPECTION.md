# P2.6C-2b Read-only Session Scanner + Classifier

## 1. 阶段目标

P2.6C-2b 在 P2.6C-2a foundations 之上建立独立 Native `SessionInspection`
模块，用于历史 Session 的只读发现、事实采集、保守分类和单 Session 错误隔离。
本阶段只生成观察结果，不执行恢复、对账或任何文件/Manifest 变更。

基点为本地 foundations checkpoint：
`6c0fc2b5a0bdf76993f92443c7c6104992685429`。

## 2. 非目标

本阶段不实现：

- Manifest 写回、revision 推进或 CAS；
- Publish/Completed 推进；
- delete、cleanup、rename、move、repair 或 recovery；
- persistent file identity schema；
- cross-process lifetime owner；
- operation-time mutation revalidation；
- Managed startup、Recovery UI 或 Native ABI；
- P2.6C-3a、P2.6C-3b 或 P2.6D。

## 3. SessionInspection 职责与调用链

正式只读链为：

```text
RecordingOutputRoot
  -> exact SessionsRoot contract
  -> handle-based SessionsRoot validation
  -> FindFirstFileW/FindNextFileW immediate children only
  -> canonical physical SessionId directory filter
  -> fixed manifest.json handle-based validation
  -> SessionManifestStore.ParseManifest structured result
  -> untrusted Manifest paths checked through SessionPathSafety
  -> filesystem facts
  -> explicit-priority classifier
  -> SessionInspectionResult
```

Scanner 直接复用 `RecordingSessionIdentity`、`RecordingOutputRoot`、
`SessionManifest` structured parser 与 `SessionPathSafety`，未复制 GUID parser、JSON
parser、output-root 拼接或 containment 逻辑。它未接入 `VideoEncoderConsumer`、
`PreviewEngine`、`RecordingController` 或 UI。

## 4. Scan-level result

`SessionScanResult` 独立表达：

- `Success`；
- `SessionsRootAbsent`；
- `SessionsRootInaccessible`；
- `SessionsRootUnsafe`；
- `IoFailure`；
- `PartialTruncated`。

结果同时保存 root PathSafety facts、观察到的 entry 数、entry 上限、是否截断、
规范 Session 结果、非规范 entry 诊断和 sessions-only discovery blind spot 标志。
`SessionsRoot` 不存在是合法空现场；Scanner 不为扫描创建它。

Shared resolver 的唯一契约为：
`SessionsRoot = MediaOutputRoot / "sessions"`。传入不符合该精确契约的 root
resolution 会 fail-closed 为 `SessionsRootUnsafe`，不能借 Scanner 枚举其他目录。

## 5. 枚举边界

Scanner 只枚举 `SessionsRoot` 的 immediate children，不递归 media root、用户磁盘或
Manifest 指向的目录。只有 canonical 36 字符、大写、无花括号 GUID 物理目录进入
Session inspection。非 canonical 目录、普通文件和 reparse entry 只记录为
`UnrecognizedSessionEntry`，不深入、不删除、不修改。

Manifest 首次创建从未成功、因而连 Session 目录也不存在时，media root 中的孤立
`.partial.mp4`/`.mp4` 本阶段无法发现。测试明确证明 Scanner 不枚举该文件；这是已知
sessions-only discovery blind spot，不通过扩大到 media-root 扫描掩盖。

## 6. Structured Manifest ParseResult 映射

Scanner 直接消费下列 typed statuses，不解析诊断文字：

| Parse status | Scanner 结果 |
| --- | --- |
| `Valid` | 进入 Manifest/filesystem 交叉分类 |
| `NotFound` | `ManifestMissing` |
| `Inaccessible` | `UnknownRetain` + I/O/inaccessible reason |
| `MalformedJson` | `ManifestCorrupt` |
| `UnsupportedSchema` | `UnknownRetain`，绝不当 corrupt |
| `SemanticInvalid` | 普通语义损坏为 `ManifestCorrupt`；identity/path/published-path 冲突为 `FilesystemConflict` |
| `UnknownOrFutureState` | `UnknownRetain` |
| `IoFailure` | `UnknownRetain` |

为避免 Scanner 复制 JSON parser，内部 ParseResult 增加 typed semantic issue：
`SessionIdentityMismatch`、`PathPolicyViolation`、`PublishedPathMismatch` 和 `Other`。
这不改变 Manifest schema、Native ABI、writer validator 严格度或兼容 `LoadManifest`
返回语义。

## 7. Session identity

物理目录必须使用 writer canonical SessionId。Manifest reader 仍按 GUID identity 接受
花括号/大小写历史表示并 normalize 为 canonical；该兼容不放宽物理目录或 media leaf。
Manifest identity 与目录 GUID identity 不一致时，typed semantic issue 使结果进入
`FilesystemConflict + IdentityMismatch`，不会继续作为同一可信 Session。

## 8. Filesystem facts

每个非空 `WorkingPath`、`PlannedFinalPath`、`PublishedPath` 都视为 untrusted candidate，
并相对 `MediaOutputRoot` 调用 `SessionPathSafety`。保存的观察状态包括：

- `Exists`、`Absent`、`ParentAbsent`；
- `Inaccessible`、`IoFailure`、`Unknown`；
- `OutsideTrustedRoot`、`ReparseEncountered`、`Invalid`、`TypeMismatch`；
- regular-file handle size，以及既有 volume/file identity 诊断。

Manifest 不可读时不跟随其中路径，只探测由 trusted root + canonical SessionId 确定的
固定 working/final leaves。`Absent` 与 sharing/ACL/I/O 不确定严格分开。Planned 与
Published 在同一路径被重复观察时，当前 handle identity 不一致会降级为冲突。

`SafeForReadOnlyInspection` **不等于** `SafeForMutation`；PathSafety facts 只描述一次
观察，不授权未来写入。

## 9. 最终 Classification enum

本阶段实现 PLAN 审查关闭后的 12 个正式类别：

1. `CompletedConsistent`
2. `PublishedMetadataNeedsReconciliation`
3. `PublishOutcomeUnprovenRetain`
4. `ReadyToPublishWorkingPreserved`
5. `IncompleteWithWorkingMedia`
6. `IncompleteNoMediaRetain`
7. `PublishFailedWorkingPreserved`
8. `FinalizeOrValidationFailedWorkingPreserved`
9. `ManifestCorrupt`
10. `ManifestMissing`
11. `FilesystemConflict`
12. `UnknownRetain`

每个结果同时包含 severity 与 reason flags。所有结果的 `deleteAllowed=false`、
`reconciliationAuthorized=false`。**SessionInspection classification 不等于
authorization to reconcile。**

## 10. 分类优先级

分类器使用显式控制流，不依赖 enum 数值顺序：

1. Session/Manifest/path identity 与安全冲突；
2. filesystem inaccessible、I/O 或不稳定观察；
3. structured parser uncertainty；
4. Manifest revision re-read 变化；
5. working/final 同时存在等文件冲突；
6. Publish、Finalize、Validation 显式失败事实；
7. incomplete/working/no-media 事实；
8. Published candidate；
9. Completed consistent。

高风险事实压过乐观状态。尤其：

- `ReadyToPublish + final exists + working absent` 只能是
  `PublishOutcomeUnprovenRetain`；路径存在不证明 P2.6A rename 身份；
- 只有持久 `State=Published + publish.published=true` 且现场一致，才成为只读的
  `PublishedMetadataNeedsReconciliation` candidate；
- `Completed` 但 final 缺失、路径 reparse/越界或 identity 冲突均不能宣称成功；
- `IncompleteNoMediaRetain` 永不授权删除。

## 11. Read-only 不变量

`SessionInspection.cpp/.h` 不调用 `CreateManifest`、`UpdateManifest`、`SaveAtomic`、
`DeleteFile`、`MoveFile`、`ReplaceFile`、`WriteFile`、目录创建、remove 或 rename。
生产代码只使用 handle probe、structured read、直接子项枚举和内存分类。fixture 的文件
创建/销毁只存在于 Native Tests。

定向测试在 Scanner 前后比较完整 Manifest bytes、稳定内容 hash 与 revision，三者完全
不变；连续两次扫描同一现场得到相同 classification/reasons/revision。

## 12. 并发与事实快照边界

当前没有 cross-process lifetime owner，因此所有结果携带 `LiveOwnerUnknown`，且不能授权
动作。这不阻止纯只读观察。Scanner 在采集路径事实后重新 Parse Manifest；revision 变化
或第二次读失败时降级 `UnknownRetain + ConcurrentChange`。

这不是 CAS，也不是 operation-time revalidation。媒体对象、Manifest 或 owner 在扫描后
仍可能变化；结果只代表 point-in-time observation。

## 13. 错误隔离

每个 canonical Session 独立 inspection。坏 JSON、future schema、sharing violation、
path type mismatch 和未知异常不会终止其他 Session。根级失败与 Session 级失败分离；
per-Session 未覆盖异常降级为 `UnknownRetain + InventoryIncomplete`。

三 Session 混合测试一次扫描同时返回：正常 Completed、损坏 Manifest 和不可访问
Manifest 三个独立结果。

## 14. 资源边界

- immediate-child 枚举，无递归；
- 默认 `maximumEntries=1024`，调用方可降低；达到限制返回
  `PartialTruncated`，不暗示其余 Session 不存在；
- Manifest reader 延续 1 MiB 输入上限；
- JSON object/array nesting 上限为 128；
- `FindFirstFileW` handle 使用 RAII `FindClose`；文件/目录 probe handles 由
  `SessionPathSafety` 的 RAII 边界释放；
- Scanner 不创建线程、Timer 或后台任务。

## 17. 已知限制与 P2.6C-3 前置门禁

P2.6C-3 前仍缺：

- persistent volume identity + stable file ID 的 Manifest 证据及 rename 后身份验证；
- cross-process lifetime owner；
- revision expected-value/CAS；
- operation-time root/Session/Manifest/media reopen 与 revalidation；
- TOCTOU、reparse、hard-link/object replacement 的 mutation defense。

在这些门禁成立前，legacy/no-identity Session 永久 Retain，任何
`PublishedMetadataNeedsReconciliation` 也只是观察候选。当前固定 OutputRoot、无 Session
目录孤立媒体 blind spot、无 Managed startup/cancellation 编排均为明确限制。

## 18. 阶段结论

独立 Native Scanner 已能在严格 sessions-only、handle-based、structured-read 边界内发现
历史 Session、隔离错误、采集事实并按审查关闭后的 12 类模型保守分类。它不执行或授权
任何持久化动作。

结论：`P2.6C-2B-READONLY-SCANNER-READY`。
