## 1. CURRENT CLOSE PATH

正式应用由 `Program.Main` 在 `MainForm.cs` 上执行 `Application.Run(mainForm)`（`Program.cs:6-20`）。当前真实关闭链为：

```text
用户关闭 MainForm
-> MainForm.OnFormClosing（1945）
-> e.Cancel=true，拒绝第一次物理关闭；_closeCleanupStarted single-flight
-> ManagedCloseCoordinator.TryExecuteAsync（PreviewLifecycleController.cs:1962）
-> 立即禁用入口并 Hide，但保留 HWND
-> MainForm.CleanupAsync（2033）
-> RecordingController.StopForCloseAsync（300）
-> PreviewLifecycleController.DisposeAsync / CloseAsync（1019）
-> 再确认 Recording 已终态
-> StopRunningPreviewUnderGateAsync（1568）
-> NativePreviewSession.Stop / XbPreview_Stop
-> PreviewEngine::Stop：join Preview worker
-> PreviewRenderer::Shutdown：StopAndJoin Encoder -> Shutdown Tap -> 释放 D3D
-> NativePreviewSession.Dispose / XbPreview_Destroy
-> PostFinalClose -> BeginInvoke(Close)
-> 第二次 FormClosing 因 _closeCleanupComplete 放行
-> FormClosed -> Application.Run 返回 -> process exit
```

关键职责：

- **Recording Stop**：只终止当前 Recording；Preview 继续运行。Managed single-flight 最终进入同一个 Native `VideoEncoderConsumer::StopAndJoin`。
- **普通 Preview Stop**：`PreviewLifecycleController.StopAsync` 先停止活动 Recording，再停止 camera/Preview/Native worker；不销毁可复用 session。
- **Application Close**：MainForm 拥有最终 close transaction；它等待 Recording 终态、停止并销毁 Preview session，最后才允许 Form/Application 退出。
- **最终 Recording owner**：唯一 `RecordingController` 由 `PreviewLifecycleController.GetOrCreateRecordingController` 创建并持有；Encoder/Finalize 的唯一 Native owner 是 `VideoEncoderConsumer`。没有第二套 Close controller、Recovery 或 Recording owner。

WinForms 官方合同与该实现一致：`FormClosing` 在窗口关闭前触发，`e.Cancel=true` 会保留窗口；`Application.Run(Form)` 的消息循环在 main form 真正关闭后结束。当前代码使用第一次 cancel + cleanup 后第二次 Close，未依赖进程退出时的偶然清理。

## 2. STATE MATRIX

| 状态 | 当前可达路径 | Stop / Join / Finalize | Preview/D3D 与 Recovery 结果 |
|---|---|---|---|
| A. Idle -> Close | MainForm Close -> `StopForCloseAsync` 读取 Idle -> lifecycle Close | 不调用 Recording Stop；Preview 如运行则正常 Stop/join | session Dispose 后退出；不产生 Recovery 候选 |
| B. Recording + visible -> Close | 第一次 FormClosing 先 Hide，再进入统一 Cleanup | 调用唯一 Stop task；等待 Encoder join、Finalize、Validation、Publish | Recording 终态后才停止 Preview/D3D；成功为 Completed |
| C. Recording + minimized -> Close | 同 B；Hide 只是幂等地进入统一隐藏状态 | 与 B 完全相同 | visibility 不参与 Stop/Publish/Recovery |
| D. Recording + hidden -> Close | 同 B；不会绕过 `RecordingController` | 与 B 完全相同 | P2.7B 保证隐藏期间 Tap/Encoder 仍可运行至 Stop |
| E. Recording Starting -> Close | `StopForCloseAsync` 先 await `_startTask`，再刷新 Native Snapshot | Start 成功后进入唯一 Stop；Start 已失败则不伪造 Stop/成功 | 不会在 Start task 未收口时销毁 session |
| F. Stopping/Finalizing -> Close | 复用已有 `_stopTask`；若 Native 自主进入 Stopping，Refresh 创建正式 Stop task | 等待同一 StopAndJoin；不重复 Finalize | Close 不越过终态等待；30 s polling 仅是无 managed task 的兜底 |
| G. Completed -> Close | Snapshot 非 active，Stop/Dispose 都直接复用终态 | 不再次调用 Native StopRecording；FinalizeCount 保持 1 | 正常销毁 Preview；CompletedConsistent 不是 Recovery candidate |
| H. 真正 crash/kill | 不进入 MainForm graceful Close | 不承诺执行 Stop/Finalize | P2.6 Manifest/Startup Scan 按 crash window retain/reconcile；不会伪装 Completed |

## 3. RECORDING OWNERSHIP

- `MainForm` 只拥有关闭事务和用户反馈，不直接拥有 Encoder。
- `PreviewLifecycleController` 拥有唯一 Native session 和唯一 `RecordingController`（`PreviewLifecycleController.cs:25-26,113-123`）。
- `RecordingController` 以 `_startTask` / `_stopTask` 和 `_gate` 实现 Start/Stop single-flight（`RecordingController.cs:238-298`）。重复按钮 Stop、Preview Stop、Close 和 Dispose 共享同一 Stop task。
- `StopForCloseAsync` 等待 pending Start；对 Starting/Recording 调用唯一 Stop；对 Stopping 等待已有 Stop；对 Completed/Failed/Idle 不再 Stop（`RecordingController.cs:300-350`）。
- Native `PreviewEngine::StopRecording` -> `PreviewRenderer::StopRecording` -> `VideoEncoderConsumer::StopAndJoin` 是唯一 Encoder 收口链（`PreviewEngine.cpp:326-334`、`PreviewRenderer.cpp:375-379`、`VideoEncoderConsumer.cpp:1807`）。

已有 Managed 定向测试明确覆盖 duplicate Start/Stop、Close/Dispose 共用一次 Stop/Finalize，以及 Preview Close 等待终态后才 Dispose（`RecordingControllerTests.cs:269-295,392-442`）。

## 4. PREVIEW VISIBILITY IMPACT

`MainForm.OnFormClosing` 对所有初始可见状态都先调用同一个 `Hide`，然后才 Cleanup；可见、最小化和隐藏因此不会分叉出不同 Recording shutdown 语义。

P2.7B 当前生产路径中，visibility 只生成 `presentationEnabled`（`PreviewEngine.cpp:1405`）；`PreviewRenderer::RenderFrame` 在 OutputCanvas 和唯一 Tap 之后才跳过 Preview back-buffer draw/Present（`PreviewRenderer.cpp:274-320`）。因此 Close 的立即 Hide 不会提前切断 Encoder，也不会拥有 Recording Stop、Finalize、Validation、Publish 或 Recovery。

没有托盘入口或“关闭即后台运行”语义；最终 `Close()` 仍关闭唯一 MainForm 并结束应用，符合本轮产品边界。

## 5. STOP / FINALIZE / PUBLISH

Native `StopAndJoin` 先请求 Tap consumer stop，join Encoder worker，再要求以下事实全部成立才 Ready/Publish：worker exited、Finalize attempted/count=1/success、Validation success、ResidualOutstanding=0（`VideoEncoderConsumer.cpp:1807-1863`）。随后才无覆盖 Publish，并发布 Completed/OutputSuccess。

销毁顺序是安全的：

1. MainForm 等待 `StopForCloseAsync`；
2. lifecycle 再次确认 Recording 非 active；
3. Native Preview Stop join `ProcessPendingFrame` worker；
4. Renderer shutdown 以幂等 `StopAndJoin` 兜底，再 Shutdown Tap；
5. 最后释放 OutputCanvas、swap chain、context/device。

所以不存在 D3D 先销毁而 Encoder 仍运行、tap-after-free 或 application exit 早于 Finalize/Publish 的当前可达正常 Close 路径。

## 6. NORMAL CLOSE VS CRASH RECOVERY

- **正常成功 Close**：持久链为 Starting -> Recording -> Stopping -> ReadyToPublish -> Published -> Completed；Completed 必须携带 Finalize/Validation/资源/Publish 的一致事实。Startup Scan 将其分类为 `CompletedConsistent` / Info，不执行恢复。
- **正常 Close 发生真实 Stop/Finalize/Publish 失败**：Native Snapshot/Manifest 进入 Failed，OutputSuccess=false，working media 按证据保留；MainForm 对关闭前已知 active 的失败显示警告。失败不会被包装成 Completed。
- **真正 crash/kill**：Recording/Stopping working media 为 `IncompleteWithWorkingMedia`，Ready working 为 `ReadyToPublishWorkingPreserved`，rename 后 metadata 窗口为 `PublishOutcomeUnprovenRetain`。仅 P2.6 的 Startup Scan / 明确用户 Recovery 行为拥有后续处理。

P2.6 classification 源码在 `SessionInspection.cpp:477-630` 明确区分 Completed、Published、Ready、Recording/Stopping/Failed；正常成功 Close 与 crash 不共享 ownership，也不会互相冒充。

## 7. REAL RACES / BLOCKERS

反证结果：**没有 P2.7C 阻断问题。**

- Close 与按钮 Stop 同时发生：`_stopTask` single-flight，Native FinalizeCount 保持 1。
- 重复 Close：MainForm `_closeCleanupStarted` 与 `ManagedCloseCoordinator._started` 均 single-flight；只有一次 Hide/Cleanup/final Close。
- Close 发生在 `ProcessPendingFrame` 中：Recording 先 Stop；随后 `PreviewEngine::Stop` join worker，renderer/D3D 不会先释放。
- Starting/Stopping 中 Close：分别等待 `_startTask` / `_stopTask`，不越过终态。
- UI deadlock：FormClosing 在首次 await 前设置 `e.Cancel=true`；Stop/Preview Stop 通过 Task 运行和 await 完成，不使用同步 Wait 或嵌套 `Application.DoEvents`，消息循环继续运行。
- cleanup 的已知 Recording 失败被终态化并保留原始 snapshot/manifest 事实；Coordinator 对真正意外异常记录 `CleanupSucceeded=false` 后仍允许应用退出。这不会生成成功状态；若进程未完成正常收口，P2.6 的非终态持久事实仍是兜底边界。

## 8. MATURE CAPABILITIES REUSED

- P2.5：唯一 Managed RecordingController、Start/Stop single-flight、Close/Dispose 等待终态。
- P2.6A/B：working -> Finalize -> Validation -> resource zero -> atomic Publish -> Completed；Manifest 单调记录真实事实。
- P2.6C/D：启动扫描、分类、retain 与极窄显式 reconciliation；不介入正常成功 Close。
- P2.7B：Preview visibility 仅控制 presentation，不控制 Recording。
- WinForms：使用官方 FormClosing cancel 和 `Application.Run(mainForm)` 生命周期，不新增第二套 application owner。
