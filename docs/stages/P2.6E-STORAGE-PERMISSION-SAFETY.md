# P2.6E MVP Storage / Permission / Destination Safety

## 1. 阶段目标

P2.6E 为首发版本补齐录制目的地、权限、空间与运行中存储故障的最小安全闭环。它不改变 P2.6A-D 的文件发布、Manifest、扫描、恢复或实际事故语义，也不引入新的录制控制器或停止链。

## 2. 原行为审计

施工前的正式行为如下：

- `RecordingOutputRoot` 只完成固定输出根的词法解析，不验证卷是否在线、目录是否可创建、当前进程是否可写。
- 开始录制前没有 `GetDiskFreeSpaceExW` 或等价的可用空间门禁。
- 输出目录、Working 文件和 SinkWriter 在首个可接受帧到达后才创建；`CREATE_NEW` 已保证 Session Working 文件不覆盖已有文件。
- `WriteSample` 的真实 HRESULT 会进入 Encoder Failed 事实并停止 FrameTap 消费，但需要正式 `StopAndJoin` 才能完成 worker join、Finalize 尝试、Manifest 终态和 Snapshot 终态。
- 旧 cleanup 只删除“本 Session 所有、从未尝试 WriteSample、零提交、未验证且属于启动垃圾”的 Working 文件。WriteSample、Finalize、Validation、Publish 失败后的媒体默认保留。
- P2.6A 已保证 `Completed = ReadyToPublish && Published`、`OutputSuccess = Completed`。因此不存在 Finalize/Publish 已失败但仍显示 Completed 的生产路径。
- UI 会显示 Native 错误文字，缺失文字时会暴露原始 HRESULT；空间/权限类错误缺少面向用户的稳定分类。

结论：Safe Publish 的成功/保留语义已经安全，缺口集中在开始前真实目的地门禁、运行中低空间策略、Native Stopping 自动汇入 Managed single-flight Stop，以及用户可理解的存储错误。

## 3. 路径与权限验证策略

新增 Native 内部 `RecordingStorageSafety`，不扩公开 ABI。开始录制、创建 Manifest、注册 FrameTap consumer 和启动 Encoder worker 之前执行：

1. 要求 OutputRoot 非空且为绝对路径；
2. 使用真实文件系统创建必要目录或确认其存在；
3. 使用 `GetVolumePathNameW` 解析实际目标卷；
4. 在 OutputRoot 中以 `CREATE_NEW` 创建带 PID、线程、时间与尝试序号的唯一最小 probe；
5. 写入一个字节并 `FlushFileBuffers`；
6. 以 `FILE_FLAG_DELETE_ON_CLOSE` 关闭并清理 probe；
7. 使用 `GetDiskFreeSpaceExW` 读取“当前调用者可用”的卷空间。

probe 不使用覆盖语义，不接触 Session Working/Final/Manifest，名称冲突会换唯一名称重试。失败时录制保持 Failed、`activeEncoder=0`、`OutputSuccess=false`，且不创建 Working 媒体。

## 4. 磁盘空间策略

策略基于当前 H.264 bitrate 加固定安全余量：

- 固定余量：128 MiB；
- Critical：固定余量 + 30 秒目标码率数据；
- Warning：固定余量 + 120 秒目标码率数据；
- Start：固定余量 + 300 秒目标码率数据。

采用向上取整的 `bitrate / 8` 字节率。以正式默认 8 Mbps 为例：Critical 约 158 MiB、Warning 约 248 MiB、Start 约 428 MiB。该模型刻意简单、保守、可解释；不声称预测剩余录制分钟数。

开始时低于 Start 阈值直接拒绝。运行中每五秒至多查询一次，避免逐帧磁盘调用；仅测试编译可请求逐样本检查以形成确定性证据。

## 5. Warning 与 Critical 语义

- `LowSpaceWarning`：Snapshot 保持 Recording，记录明确提醒，Encoder 继续。
- `CriticalSpace`：Snapshot 转为 Stopping，Native 停止接受 FrameTap 数据；下一次正式 Managed Snapshot 刷新将启动且复用唯一 Stop task，调用原有 Native Stop、worker join、Finalize、Validation、Safe Publish 与 Manifest 生命周期。

Critical 不直接杀死 Encoder、不删除 Working、不创建第二套 shutdown 流程。若余量仍足以完成 Finalize/Publish，终态可以是真实 Completed；若任何步骤失败，则终态为 Failed 并保留素材。

## 6. 运行中存储故障

运行中卷查询或底层写入出现磁盘满、句柄磁盘满、拒绝访问、写保护、路径/设备不可用或 I/O 错误时：

- 保留原始 HRESULT 于 Native diagnostics/Snapshot；
- Snapshot 进入 Stopping，Managed 通过同一 Stop task 收口；
- `OutputSuccess=false`，不得伪造 Completed；
- 已提交媒体的 Working 不进入启动垃圾 cleanup；
- Finalize、Validation 或 Publish 的既有失败语义保持不变；
- Manifest 在正式 StopAndJoin 中记录最后可持久化事实；
- Preview 生命周期不因 Encoder 存储故障而被停止。

## 7. Safe-stop 链

正式链为：

`runtime storage fact -> Native Stopping -> RecordingController.RefreshSnapshot -> shared Stop task -> StopRecording -> worker join -> Finalize once -> Validation -> ReadyToPublish -> Safe Publish -> terminal Snapshot/Manifest`

`RecordingController.StopAsync` 现在接受 Native 已进入 Stopping 的状态；重复 UI refresh、用户 Stop 和 Close 都共享 `_stopTask`，不重复调用 Native。

## 8. 媒体保留

本阶段没有放宽删除条件。只有本 Session 所有且零 WriteSample/零提交的明确启动垃圾可删除。以下失败均默认保留有价值媒体：

- WriteSample 存储失败；
- Finalize 失败；
- Validation 失败；
- Publish 冲突、权限、路径或存储失败；
- Stop/Close 异常或未知终态。

Publish 已成功的 Final 永远不进入失败 cleanup。

## 9. 用户错误语义

Managed presentation 将常见存储 HRESULT 映射为稳定中文提示：磁盘空间不足、目录不可写、目录/设备不可用、磁盘 I/O 错误。不会把裸 HRESULT 当作首选用户文字。Recording/Stopping 期间的低空间事实显示为“提醒”，Failed 终态显示为“错误”。未知 Native 错误仍保留 Native 提供的诊断文字。

## 10. Test-only seam

`VideoEncoderLifecycleTestHooks` 仅在 `XBPREVIEW_NATIVE_TESTS` 中存在，产品 DLL 不包含测试字段或分支。它可确定性注入：

- 开始前空间/目的地结果；
- 运行时 Warning/Critical/不可用；
- 每样本检查；
- 指定提交帧数后的 WriteSample HRESULT。

测试不填满用户磁盘、不改 ACL、不使用环境变量或产品默认开启的故障路径。真实目录 probe、中文路径、文件创建、写入、Flush、卷解析和空间查询仍由正式实现验证。

## 11. 测试结果

- Release x64 solution Rebuild：PASS，0 warning / 0 error。
- P2.6E Native 定向矩阵：10/10 PASS。
  - bitrate + margin 阈值边界；
  - 真实中文可写目录、卷空间与无残留 probe；
  - 非法相对路径；
  - 开始前低空间、拒绝访问、目标不可用；
  - 运行中 Warning；
  - 运行中 Critical 安全 Stop/Finalize/Publish；
  - WriteSample 磁盘满；
  - 运行中目标失联。
- P2.6E Managed 定向：PASS；Native Stopping、重复刷新和用户 Stop 共用一次 Native Stop/Finalize，用户错误分类不暴露裸 HRESULT。
- P2.6A Safe Publish：PASS，包括正常双 Session、final 冲突、Finalize 失败、Validation 失败、启动异常、发布后 Snapshot 异常。
- P2.6D-2A 实际 pre-publish crash：43/43 PASS。
- P2.6D-2B 实际 post-rename crash/recovery：69/69 PASS。
- Native ABI v4：PASS；API 保持 `0x00040003`，RecordingSnapshot 保持 2856 bytes。
- Managed P2.6A publish mapping：PASS。
- Managed P2.5A interop：PASS。
- 完整 P2.5B 套件的纯 Controller/interop 部分已有定向 PASS；其真实 MainForm Preview case 在本机因既有 Windows Graphics Capture 服务错误 `0x80070424` 未进入录制，和存储实现无关。P2.6E 通过独立不依赖 WGC 的真实 Encoder 集成与 Managed single-flight 测试覆盖本轮闭环。

## 12. 已知限制与后续增强

本阶段明确不实现：精确剩余时长 UI、空间仪表盘、自动清理旧录像、自动换盘、云盘、网络路径完整支持、可移动盘热插拔恢复、任意损坏媒体修复，以及 P2.7/P2.8/P2.9。

运行期空间查询依赖有视频帧到达；没有新帧时不会继续写数据，因此不会为静态无写入状态建立额外线程。同步 Native 查询本身不具备可取消异步 I/O，这属于首发后的增强范围。

## 13. 阶段结论

P2.6E 在不改变 Safe Publish、Manifest、Recovery、公开 ABI 和 Preview 生命周期的前提下，建立了首发所需的目的地/权限门禁、保守空间门禁、运行时 warning/critical、安全停止、失败保留与用户提示闭环。
