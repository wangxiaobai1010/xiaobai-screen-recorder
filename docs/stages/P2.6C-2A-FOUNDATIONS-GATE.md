# P2.6C-2a Inspection Foundations 总门禁

日期：2026-08-07

分支：`feature/p2.6c-inspection-foundations`

基点：`c0805f4e678117ce6a5041deefb37a6794844066`

## 1. 门禁目标与审查边界

本门禁复核 P2.6C-2a-1 Inspection Contracts 与 P2.6C-2a-2 Handle-based Path
Safety 是否共同形成内部一致、可供 P2.6C-2b Read-only Scanner + Classifier 复用的基础层。

本轮只审查合同连接、复跑最小定向测试并新增本报告。没有修改生产行为、ABI、Manifest
schema 或测试，没有实现 Scanner、Classifier、Session 枚举、reconciliation、persistent
file identity、live owner、revision CAS、Recovery UI 或 P2.6D。

## 2. 四套基础合同

### 2.1 Session identity

唯一事实源是 `RecordingSessionIdentity.h/.cpp`：

- Writer 使用 `FormatCanonicalRecordingSessionId`，输出 36 字符、无花括号、大写 GUID；
- `PreviewEngine`、正式配置、媒体 leaf、Manifest Writer 与 Session 目录均使用该 canonical
  form；
- Reader 使用 `NormalizeRecordingSessionId`，只兼容严格 bare/braced 形状及大小写变体，
  按 GUID identity 统一回 canonical；
- `IsCanonicalRecordingSessionId` 是 Writer/物理 Session 目录门禁；Reader compatibility
  不会放宽物理目录或媒体 leaf；
- Native 内没有第二套 GUID formatter/parser。`StringFromGUID2`/`CLSIDFromString` 只封装在
  该模块，其他生产调用点复用公开内部合同。

未来 Scanner 枚举目录后可直接用 `IsCanonicalRecordingSessionId` 判定物理 Session 目录，
并用同一 identity 规则核对 Manifest，不需要复制 GUID 规则。

### 2.2 Shared OutputRoot

唯一正式事实源是 `RecordingOutputRoot.h/.cpp`：

- `ResolveRecordingOutputRoots` 定义正式 `mediaOutputRoot`；
- `ResolveRecordingOutputRootsFromManagedRoot` 唯一派生
  `sessionsRoot = mediaOutputRoot / "sessions"`；
- `VideoEncoderConfig`、`SessionManifestStore` 与 `SessionPathSafety` 均复用该结果；
- resolver 只定义地址，不创建目录、不访问媒体、不宣称文件系统安全。

保留的 `ResolveArtifactsRoot` 只服务历史 P2.4 diagnostic encoder，不定义正式
P2.5/P2.6 Recording/Manifest/Scanner root，因而不构成第二套 Scanner 事实源。未来 Scanner
不需要也不得自行拼接 `root + "\\sessions"`。

### 2.3 Structured Manifest ParseResult

唯一只读读取入口是 `SessionManifestStore::ParseManifest`：

- `Valid`；
- `NotFound`；
- `Inaccessible`；
- `MalformedJson`；
- `UnsupportedSchema`；
- `SemanticInvalid`；
- `UnknownOrFutureState`；
- `IoFailure`。

结果保留 HRESULT 与 observed schema；仅 `Valid` 改写调用方 output。解析顺序、JSON/schema
验证、semantic validation、深度上限和异常分类均在现有模块内完成。`LoadManifest` 只是
委托该入口的 compatibility wrapper，不是第二套 parser。未来 Scanner 无需解析错误文字、
二次判断 schema 或重写 JSON validator。

### 2.4 Handle-based Path Safety

唯一只读路径授权入口是 `SessionPathSafety.h/.cpp`：

- `InspectPathForReadOnly` 提供通用 TrustedRoot/Candidate handle 事实；
- `InspectCanonicalSessionDirectoryForReadOnly` 固定
  `sessionsRoot + canonical SessionId`；
- `InspectRecordingMediaPathForReadOnly` 固定使用 `mediaOutputRoot`；
- root、intermediate、leaf 逐组件打开，读取 final path、reparse、volume/file identity；
- containment 使用路径组件边界、handle-resolved final path 和同卷事实，不使用
  `string starts_with`；
- 任意 reparse 都不能进入 Safe；Absent、ParentAbsent、Inaccessible、IoFailure 分离。

类型名、接口注释和阶段报告均明确：`SafeForReadOnlyInspection != SafeForMutation`。结果是
point-in-time 只读事实，不授权 delete/rename/overwrite/publish/reconciliation。

## 3. 事实来源唯一性结论

| 事实 | 唯一来源 | 其他模块职责 |
| --- | --- | --- |
| Session GUID 格式/identity | `RecordingSessionIdentity` | 只调用，不重写规则 |
| Media/Sessions root 地址 | `RecordingOutputRoot` | Writer、Manifest、未来 Scanner 复用 |
| Manifest 内容读取/分类 | `SessionManifestStore::ParseManifest` | Scanner 消费结构化结果 |
| 路径只读安全事实 | `SessionPathSafety` | Scanner 消费结果，不自行 canonicalize 授权 |

未发现需要 Scanner 复制 formatter、root 拼接、JSON validator、error-string parser 或
`GetFullPath + starts_with` 路径授权逻辑的缺口。

## 4. 合同边界与冲突复核

### 4.1 ParseResult NotFound 与 PathSafety Absent

两者不混用：

- Manifest `ParseResult::NotFound` 只描述 `manifest.json` 实际读取时的结果；
- `PathSafety::Absent/ParentAbsent` 描述任意候选路径在已验证 root/parent chain 下的文件系统
  事实与只读访问边界。

`ParseResult::NotFound` 不能代替 containment/reparse 证明；`PathSafety::Absent` 也不解释
Manifest schema。若 PathSafety 和实际读取之间现场变化，Scanner 必须保留两次观察并按
不确定事实 Retain，不能把任一结果升级成成功。

### 4.2 UnsupportedSchema 与 FutureState

`UnsupportedSchema` 和 `UnknownOrFutureState` 已独立于 corrupt/semantic-invalid。未来 Scanner
可直接分类为 Retain，无需放宽 schema-v1 validator，也不得猜测未来状态含义。

### 4.3 Reader compatibility 与物理 Session 目录

Reader 的 braced/case compatibility 只适用于 Manifest identity。物理 Session 目录仍必须
通过 `IsCanonicalRecordingSessionId`；`InspectCanonicalSessionDirectoryForReadOnly` 同样拒绝
非 canonical 文本。不存在“兼容 Reader 等于接受 braced 目录”的合同泄漏。

### 4.4 Resolver 与 TrustedRoot validation

职责互补而非冲突：resolver 定义产品地址且无副作用；PathSafety 验证该地址在当前文件系统
是否真实存在、是目录、可打开、无 reparse 且能建立 final-path/volume handle 事实。
resolver 成功不自动产生 Safe，PathSafety 也不创建缺失 root。

### 4.5 Reparse、Absent 与失败隔离

- root、intermediate、leaf 任意 reparse 均为 `ReparseEncountered`；不跟随 root 内 reparse；
- 只有安全 parent chain 已验证且 leaf open 明确 not-found 才是 `Absent`；
- parent 缺失、AccessDenied/SharingViolation 和其他 I/O 各自保留；
- ParseResult 与 PathSafety 都是无共享可变状态、结构化、fail-closed 的单次调用，一个
  Session 的失败天然可以由未来 Scanner 隔离并继续检查其他 Session。

## 5. Future Scanner 推荐调用链

现有基础层支持以下 2b 调用关系而无需复制安全逻辑：

```text
Managed startup orchestration
  -> future Native SessionInspection
  -> ResolveRecordingOutputRoots
  -> InspectPathForReadOnly(SessionsRoot, SessionsRoot, Directory)
  -> enumerate SessionsRoot（2b 实现，只读且有资源/取消边界）
  -> IsCanonicalRecordingSessionId(directory leaf)
  -> InspectCanonicalSessionDirectoryForReadOnly
  -> InspectPathForReadOnly(SessionDirectory, manifest.json, RegularFile)
  -> SessionManifestStore::ParseManifest
  -> InspectRecordingMediaPathForReadOnly(Working/PlannedFinal/Published)
  -> pure Classifier
```

Manifest 文件自身必须先通过派生路径的 PathSafety；Manifest 中的媒体路径在 parse 成功后
仍逐一作为 untrusted candidate 检查。现有通用 API 已支持该顺序。本门禁没有实现调用链。

PathSafety 是 point-in-time 观察；2b 若后续 read 返回与 probe 不同的事实，必须 Retain/
标记 inventory 不完整。它不能把早先 Safe 缓存为长期授权。

## 6. Scanner 前四个 blocker

| Scanner 前 blocker | 状态 | 关闭证据 |
| --- | --- | --- |
| SessionId canonical contract | **CLOSED** | 唯一 formatter/parser、正式生产链与 contract matrix |
| Shared OutputRoot resolver | **CLOSED** | Writer/Manifest 共用 roots、无副作用、中文/正式路径测试 |
| Structured Manifest ParseResult | **CLOSED** | 八类结果、严格 schema、异常/深度/输出不变测试 |
| Handle-based Path Safety | **CLOSED** | 逐组件 handle proof、真实 junction/sharing 与 25 项矩阵 |

四项均 CLOSED，未发现新的纯只读 Scanner blocker。P2.6C-2b 可以在获得独立开工指令后
开始；本报告本身不授权开工。

## 7. Reconciliation 前仍开放的 prerequisites

以下事项保持 OPEN：

- persistent volume/file identity；
- cross-process Session lifetime owner；
- Manifest revision re-read / expected revision / CAS；
- operation-time reopen/revalidation；
- mutation-level hard-link defense；
- mutation-level reparse/object-replacement/TOCTOU defense。

它们阻止一切自动 reconciliation 或媒体 mutation，但不阻止仅观察、结构化分类并对所有
不确定事实 Retain 的 2b Scanner。2b 不得删除、移动、发布、修复或写回 Manifest。

## 9. 已知限制

- OutputRoot 当前固定，未实现 historical-root registry；
- sessions-only Scanner 仍无法发现没有 Session 目录的孤立媒体；
- UNC、extended/device namespace 不在当前受支持路径合同内；
- reparse 一律 Retain，不智能跟随；
- legacy/no-identity Session 只能 Retain；
- `IncompleteNoMediaRetain` 不能成为自动删除依据；
- PathSafety 不解析 MP4、不判断 working 可恢复性；
- 本门禁不解决任何 mutation 级并发/TOCTOU 安全。

## 10. 门禁结论

P2.6C-2a-1 与 2a-2 已形成四个事实来源唯一、边界互补、fail-closed 的 Inspection
Foundations。现有接口足以让 P2.6C-2b 在不复制 GUID、root、Manifest parser 或路径授权
逻辑的前提下实现纯只读 Scanner + Classifier。

结论：`P2.6C-2A-FOUNDATIONS-GATE-PASS`。
