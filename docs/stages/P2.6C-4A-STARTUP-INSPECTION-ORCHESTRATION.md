# P2.6C-4a Production Startup Session Inspection Orchestration

## 1. 目标与非目标

本切片把已经通过安全门禁的 Native 只读 `SessionInspection` 接入正式
`XbPreview.Host` 启动生命周期。正式 App 在核心初始化成功后只调度一次历史
Session 扫描，并把结构化结果送入 Managed orchestration 层；历史扫描不是当前
Preview 或 Recording 的状态真相。

本阶段不实现 Recovery UI，不执行 reconciliation，不修改 Manifest，不移动、删除或
恢复媒体，不抢占活动 Session，也不改变 Recording Start/Stop、Safe Publish 或
`XbRecordingSnapshot` 的既有语义。

## 2. 正式 App startup 调用链

生产调用链为：

```text
MainForm.OnShown
  -> 创建并确认 MainForm / PreviewSurface handle
  -> 确定 diagnostic directory
  -> 构造 PreviewLifecycleController
  -> await PreviewLifecycleController.InitializeAsync
  -> 初始化成功且 startup generation 仍有效
  -> TryScheduleStartupInspection(diagnosticDirectory)
  -> GetOrCreateRecordingController
  -> RequestResizeAsync / Timer / 正式自动 Preview 启动链继续

TryScheduleStartupInspection
  -> NativeHistoricalSessionInspector
  -> StartupInspectionCoordinator.StartAsync
  -> Task.Run 执行同步 Native scan
  -> immutable StartupInspectionSnapshot
  -> Managed startup diagnostic / 未来 4b 只读候选入口
```

调用点位于 `PreviewLifecycleController.InitializeAsync` 成功之后、创建
`RecordingController` 之前。此时输出根合同和 Native session 已可用，但扫描不依赖
当前 `RecordingSnapshot`，也不会与随后创建的新录制 Session 混为一谈。

## 3. Native / Managed bridge 决策

此前没有能够安全承载 `SessionInspection` 结果的 Managed bridge。本阶段没有在
MainForm 复制 JSON parser、classification、Path Safety、GUID 或 owner 判断，而是新增
独立、版本化、只读 C ABI。它不复用 `XbRecordingSnapshot`，也不使用 JSON 字符串逃避
结构化合同。

bridge 使用 opaque scan handle：Begin 冻结一次扫描结果，Managed 按 index 读取 item，
UTF-16 字段使用 required-length probe 后再复制，最终在成功、异常和取消路径中都销毁
handle。Native classification 与 ABI enum 之间使用显式映射，不依赖内部枚举 ordinal。

生产路径只包含 `SessionInspection`。没有 `NarrowReconciler` 调用，也没有 Manifest
save、媒体 delete/move/publish 或 schema 2 到 schema 3 的转换。

## 4. ABI 决策与版本

- 产品 API 从 `0x00040001` 递增为 `0x00040002`；ABI major 仍为 v4。
- 独立 Historical Session Scan ABI 为 `0x00010001`。
- scan layout/options/summary/item 分别为 32/40/64/192 bytes，Pack=8，pointer=8，
  `wchar_t`=2。
- `XbRecordingSnapshot` 仍为 2856 bytes；旧结构字段和 offset 未改变。
- scan options、layout、item、保留字段、版本和大小均 fail-closed。
- Managed `StructLayout`、size 和关键 offset 与 Native static assertions/ABI layout export
  一致。
- SessionId 只接受 36 字符、无花括号、大写 canonical GUID。
- 两次 UTF-16 读取的 required chars 包含终止 NUL；缓冲不足返回明确错误且不发布截断
  字符串。

Managed bridge 使用实际加载的 `XbPreview.Native.dll` 校验产品 API 和 scan ABI；未知或
不兼容布局不会被猜测读取。

## 5. Startup scheduling

`MainForm` 的默认 inspector factory 创建正式
`NativeHistoricalSessionInspector`。构造窗体时不扫描磁盘；只有 `OnShown` 的核心
Initialize 成功后才调度。同步 Native scan 被 Coordinator 放入线程池执行，MainForm
不 await 扫描完成，Resize、RecordingController 建立和正常 Preview 启动链继续运行。

扫描失败被转换为 Managed `Failed` terminal snapshot 和内部诊断，不进入
`OnShown` fatal-error 路径，不阻止 Preview，也不阻止用户正常录制。

## 6. Single-flight

MainForm 以原子 `_startupInspectionScheduleAttempted` 保证同一窗体启动只调度一次；
Shown 重入、Preview 重连或重复调用不会创建第二个 scanner。Coordinator 内部只持有一个
`_runTask`，并发或重复 `StartAsync` 返回同一个 Task，不维护第二套扫描状态。

扫描结果在一次 Begin 时冻结为 immutable handle 内容；Managed 对外保存的
`StartupInspectionSnapshot` 同样不可变。

## 7. UI 线程非阻塞证据

真实 MainForm 接线测试加载 Release 输出中的实际 `XbPreview.Host.dll`，在单一 STA
`Application.Run` 消息循环中执行真实 `MainForm.OnShown`。测试通过正式内部依赖工厂
注入一个受控阻塞 inspector；生产默认构造函数仍使用 Native inspector，没有测试模式、
环境变量或条件编译分支。

为避免把 4a 结果误绑定到已知可能受系统环境影响的 WGC service，测试只在 Show 前把
现有 `_automaticStartAttempted` 预置为 true，因此不进入自动 WGC Start；它仍完整执行
handle 创建、真实 Native session Initialize、`OnShown` 调度、RecordingController 建立和
Resize。inspector 保持阻塞期间，测试确认：

- `_recordingController` 已建立；
- STA `BeginInvoke` ping 正常执行；
- inspector 在线程池线程而非 STA 线程运行；
- 扫描尚未释放，MainForm 仍可继续处理消息。

这证明 startup orchestration 不依赖 WGC Preview 成功，也不会同步阻塞 UI。WGC 本身不在
本阶段重新验收；现有 Preview/Recording 回归继续覆盖产品路径。

## 8. Close / Dispose 安全

FormClosing 先使 startup generation 失效并请求取消。Cleanup 先沿既有
`StopForCloseAsync` 完成活动录制的 Stop/Finalize，再退订 inspection callback、等待
Coordinator 的 Native worker 到达真实终态并 Dispose，最后释放 Preview lifecycle。
历史扫描不会排在用户录制安全收尾之前。

callback 在入队前和 UI lambda 执行时都重新检查 Coordinator 身份、当前 snapshot、
`_closing`、`IsDisposed` 和 `Disposing`。测试在扫描未完成时关闭实际 MainForm，确认取消
被观察、FormClosed 后才退出消息循环、没有 late callback crash，STA thread 最终 join，
无未观察任务异常或残留 UI 线程。

Native scan 是同步、进程内调用，不能假装在 C 调用中已经中断。关闭会等待最多 1024
entries 的有界扫描真实返回，避免留下后台 Native 调用、opaque handle 或 UAF。

## 9. Managed startup result 模型

scan-level 结果包含 overall status、HRESULT diagnostic、wall-clock duration、发现 Session
数、未识别条目数、返回条目数、上限、truncated/partial 高层事实以及
sessions-only blind-spot 标记。

per-session DTO 只包含 canonical SessionId、classification、severity/reasons、
retain-user-media、working/final existence 高层事实、Native 允许的 display-safe path、
Manifest parse status/HRESULT 和 owner state/HRESULT。它不暴露 raw SessionDirectory、
ManifestPath 或 mutation authority。

只有 Native handle-based filesystem fact 为 `Exists` 的候选才可成为
`DisplaySafePath`。Managed 还会 fail-closed 校验 enum、0/1 bool、canonical GUID、完整
绝对路径和 count 一致性。

## 10. Observation 不等于授权

明确合同：

```text
StartupInspectionSnapshot != Reconciliation Authorization
```

Native item 中 `deleteAllowed` 和 `reconciliationAuthorized` 必须始终为 false；任何非零值
都会使 Managed bridge fail-closed，而且这两个字段不会进入 Host DTO 或未来 UI。

即使 4b 以后由用户选择“处理”，也必须重新调用 `NarrowReconciler`，由 operation-time
Guard 重新取得 owner、revision、path、identity 与媒体证据。缓存的 startup observation
永远不能直接修改 Manifest 或媒体。

## 11. Multi-instance / Active owner 边界

另一个进程仍持有 Session lifetime owner 时，scanner 只返回 owner 事实与 Retain 分类。
它不抢占 owner、不结束或 kill 另一实例，也不把单一 Active Session 提升为 scan-level
失败。正常的其他历史 Session 仍独立返回。

## 12. 错误隔离

不存在或为空的 SessionsRoot 是可结构化表达的正常结果。单个 corrupt、unsupported、
unsafe/reparse、inaccessible 或 future-state Session 只影响该 item；不会阻断其他 item，
也不会阻止 Host 启动。scan-level Native/transport 错误被映射为明确 status/HRESULT，
不从异常字符串推导结构化分类。

Coordinator 捕获 backend exception 并发布失败 snapshot；MainForm 的 factory、schedule、
diagnostic 和 dispose 路径也独立保护，因此历史恢复旁路失败不扩散到 Preview/Recording。

## 13. 资源上限与可观测性

正式入口继续复用 2b 的 manifest 大小/深度限制、每 Session 错误隔离和 path-safety
合同；最大扫描条目为 1024，不解除既有资源上限。summary 记录 wall-clock duration、
session/result count 和 truncated/partial 事实。opaque handle 与 UTF-16 buffer 均有明确
所有权，没有 helper process。

## 16. 环境限制与已知取舍

真实 MainForm 4a 测试有意不启动 WGC；这是为了把 startup inspection 编排证据与系统
WGC service 可用性分离，不是用短路替代产品逻辑。正式默认 MainForm 仍执行原自动
Preview 启动链。本阶段也没有性能 benchmark；只证明扫描有边界、在后台执行且记录实际
duration。

同步 Native scan 在单次 C 调用内部没有 cooperative cancellation，因此 close 选择等待
有界扫描真实返回，而不是遗留后台调用。这是当前安全取舍，不是取消已完成的伪事实。

## 17. P2.6C-4b 依赖

4b 可以消费本阶段 immutable Managed observation，决定向用户展示哪些只读候选、状态和
安全路径。它不得绕过 Native classification，也不得把缓存结果当成操作授权。任何用户
触发的处理必须重新进入 NarrowReconciler 与 operation-time evidence guard。

4b 仍需单独设计最小用户文案、候选选择、刷新和错误展示；本阶段没有弹窗、恢复中心、
自动 reconciliation 或媒体修复。

## 阶段结论

正式 Host 已在核心 Initialize 后以 single-flight、UI 非阻塞、失败旁路和 close-safe 的
方式调度只读 Native SessionInspection。结构化结果到达 Managed orchestration，但没有
任何 mutation authority 或自动处理路径。
