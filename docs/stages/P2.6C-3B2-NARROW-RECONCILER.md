# P2.6C-3b-2 Narrow Reconciler

## 1. 目标与非目标

本切片实现第一条、也是当前唯一允许的历史 Session Manifest 元数据
reconciliation：严格 schema 2 `ReadyToPublish` 到严格 schema 3
`ReconciledCompleted`。它不枚举 Session、不恢复或修复媒体、不清理文件、不接入
Managed startup/UI，也不改变普通录制、Native ABI 或 Manifest schema 2 writer。

## 2. 模块职责

`NarrowReconciler` 只处理调用方显式指定的 canonical SessionId 和 expected
revision。它复用 `ReconciliationEvidenceGuard` 取得 operation-time 证据，再执行
Source Eligibility、目标构造、mutation whitelist 和专用 expected-revision CAS。
Scanner 不能通过 classification 直接授权该操作。

## 3. 唯一 Source Eligibility

唯一 source 是 strict schema 2 `ReadyToPublish`，并要求：媒体已提交、worker 已
退出、录制资源已释放、残留为零、Finalize 一次且成功、Validation 已执行且成功、
持久 Working FILE_ID_INFO identity 完整有效。历史 publish 结果必须仍未知；已有
publish、PublishedPath、post-publish verification、reconciliation 或冲突 error facts
均拒绝。结果类型区分 `NotEligibleState`、`InvalidSourceFacts` 与
`SemanticConflict`。

## 4. 唯一 Target

唯一 target 是 schema 3 `ReconciledCompleted`。它只表达：operation-time 证据证明
同一 underlying media object 当前安全位于 `plannedFinalPath`。它不声称历史
Native `MoveFileExW` 已知成功。

## 5. Guard 调用顺序

调用顺序固定为：structured initial read（仅 schema/idempotency/revision）→
`ReconciliationEvidenceGuard` → operation-time current Manifest Source Eligibility
→ whitelist target construction → dedicated CAS。只有 `EvidenceComplete` 会进入资格
判断和 mutation。身份缺失、Working 存在、active owner、路径/reparse/hard-link、
final 缺失或身份不匹配均 fail closed。

## 6. Mutation whitelist

唯一允许变化为：schema 2→3、revision N→N+1、`updatedAtUtc`、
`ReadyToPublish`→`ReconciledCompleted` 以及新增 reconciliation provenance。
其余字段逐字段 semantic-equal；JSON 字段顺序和格式不参与比较。

## 7. Immutable validator

`ValidateNarrowReconciliationMutation` 显式比较 Session identity、路径、媒体提交、
Finalize、Validation、publish、persistent identity、post-publish verification、资源和
error facts。任一非白名单变化返回 `ImmutableFieldViolation` 且不写盘。

## 8. Single nowUtc

成功目标只捕获一次 `nowUtc`，同时写入 `updatedAtUtc` 与
`reconciliation.reconciledAtUtc`。专用 CAS 不再调用内部 clock，也不会覆盖该值。
失败和幂等路径不产生持久 timestamp 变化。

## 9. Schema 2 到 schema 3 构造

provenance 固定为：`reconciled=true`、唯一 reconciliation kind、
`sourceRevision=N`、唯一 evidence kind、`originalPublishResultKnown=false`，且
`confirmedFinalPath` 来自 Guard 实际持有并验证的 final candidate。

## 10. Expected-revision CAS

`SessionManifestWriteTransaction::CompareExchangeNarrowReconciliation` 复用现有
write lock、锁内 reload、完整 current 内容一致性验证、temp/flush/verify/atomic
replace。它只接受 strict schema 2 source 和已经 whitelist 的 schema 3 N+1 target；
通用 schema 2 CAS 行为保持不变。真实 ReplaceFile 失败保留原 schema 2 bytes，
不存在半 schema 3。

## 11. AlreadyReconciled

初始调用必须 strict structured reload。合法 schema 3 `ReconciledCompleted` 返回
`AlreadyReconciled`，不增加 revision、不改 timestamp、不重写 Manifest。

## 12. Concurrent loser semantic equivalence

两个调用基于 N 时，winner 只写 N+1。loser 在 revision/concurrent mismatch 后重新
读取 current；若严格 schema 3 target 与原 source 在 provenance 和全部 immutable
facts 上 semantic-equivalent，则返回 `AlreadyReconciled`。两个调用各自未持久的
timestamp 差异可忽略，不触发 N+2；非等价变化返回 `RevisionChanged`。

## 13. Result 模型

结构化结果覆盖 `Reconciled`、`AlreadyReconciled`、`NotEligibleState`、
`InvalidSourceFacts`、`SemanticConflict`、`GuardRejected`、`RevisionChanged`、
`ConcurrentChange`、`ImmutableFieldViolation`、`UnsupportedSchema`、
`EvidenceInsufficient`、`CasFailed`、`IoFailure` 和 `Unknown`，并保留 HRESULT、
expected/observed revision、Guard 与 CAS status。

## 14. 用户手工同卷移动场景

测试 fixture 先创建 strict schema 2 `ReadyToPublish` 并持久化 Working FILE_ID，随后
用 fixture-only `MoveFileExW(..., MOVEFILE_WRITE_THROUGH)` 模拟外部同卷
Working→planned-final rename，再释放 owner。生产 `NarrowReconciler` 本身不包含任何
Move/Copy/Delete/rename/remove/truncate/write-media API。

## 15. 媒体零修改证明

成功 CAS 前后分别采集真实 final 的 SHA-256、byte size、FILE_ID_INFO、creation time
和 last-write time；65 项矩阵断言它们全部相同。held final handle 只用于证据读取，
没有写权限。

## 16. Scanner 保持无权

成功后 read-only scanner 分类为 `ReconciledCompletedConsistent`，而不是
`CompletedConsistent`；`deleteAllowed=false` 且
`reconciliationAuthorized=false`。Scanner 没有调用 `NarrowReconciler`。

## 17. 正常 Recording 不受影响

`VideoEncoderConsumer` 和普通 Recording 未接入新模块，仍只写 schema 2。P2.6A
Native `Published`/`Completed` 语义保持原样。Native API 仍为 `0x00040001`，
`XbRecordingSnapshot` 仍为 2856 bytes。

## 18. 定向测试

`--p2.6c3b2-narrow-reconciler` 共 65 项，覆盖 happy path、幂等、十类 Guard 拒绝、
三类 Source Eligibility、schema 1/2/3/future、五类 immutable violation、真实双线程
winner/loser、非等价并发、schema 3 负向字段、真实 atomic replace 失败，以及媒体
零修改。Release clean Rebuild 后该矩阵 PASS；ABI v4 PASS。

## 19. 回归

以下回归 PASS：schema3 consumers 44、3a3 Guard 35、3a2 lifetime owner 32、3a1
identity 25、2b scanner 35、2a2 path safety 25、2a1 contracts、P2.6B-1 和
P2.6B-2。`--p2.6a3-publish` 首次和合同允许的唯一一次隔离复核均在既有
`first tap frame creates one fixed six-texture generation and drops transition frame`
断言失败。当前差异未修改 FrameTap/NV12/Encoder 核心；按本任务明确停止线，稳定
复现使本轮结论为 BLOCKED，未进行第三次复核或修复。

## 20. 已知限制

本模块不发现候选、不自动运行、不证明历史 Native publish 动作、不修改媒体、不提供
恢复 UI。内部 scheduling hook 仅用于确定性并发观察，默认关闭，不能提供证据、绕过
Guard 或授权 mutation。P2.6B 远程同步仍为 `REMOTE-SYNC-PENDING`。

## 21. P2.6C-4 前仍缺内容

在进入 Managed startup 和用户可见 recovery candidates 前，需先独立处置并重新验证
上述稳定 FrameTap 回归阻断；该处置及复验已记录在第 22 节。后续仍需完成 3b 的聚焦
审查/冻结，当前不得接入 startup 或 UI。

## 22. FrameTap blocker resolution

原 P2.6A-3 回归把一次非阻塞 `ObserveAndCopy` 的具体调度结果写成固定合同：第一次
调用必须立即取得 Tap mutex、建立一代 6 张纹理，并把 transition frame 计为一次
generation mismatch。失败现场的实际事实是 `generationChangeCount=0`、
`texturesCreated=0`、`framesDroppedGenerationMismatch=0`、
`framesDroppedLockBusy=1`；生产 `std::try_to_lock` 明确允许该 lock-busy 丢帧。

detached A/B 诊断确认 3b-1 checkpoint `37d6d2d` 的 clean Release x64 与
`--p2.6a3-publish` PASS；当前 3b-2 新编译单元和测试链接布局稳定暴露了既有 fixture
时序假设。FrameTap、NV12、texture pool 和 Encoder 生产逻辑均未修改，因此处置被
严格限定为 **TEST FIXTURE / TEST CONTRACT FIX**。

`PrimeTapGeneration` 现在记录 baseline，在最多 64 次且最多 250ms 的双重边界内提交
prime frame。建立 generation 前只允许 `framesDroppedLockBusy` 增长；任何其他状态
立即失败。成功后仍严格要求 generation change delta=1、textures created delta=6、
generation mismatch delta=1、无 copied/enqueued prime frame、无 queue/pool 异常、
无 stale/late return、无 double return/invalid transition、无 outstanding resource。
bounded sequence 若不能建立 generation 会输出 attempts、generation、mismatch、
lock-busy、texture、observed/copied/enqueued、input-frame 和 residual counters，不会
无限重试或以“未崩溃”代替安全事实。

修复后 clean Release x64 Rebuild 为 0 warning / 0 error，
`--p2.6a3-publish` 六组矩阵 PASS 且 `ResidualOutstanding=0`。完整定向回归结果：
Narrow Reconciler 65/65、schema3 consumers 44、3a3 Guard 35、3a2 owner 32、3a1
identity 25、2b scanner 35、2a2 Path Safety 25、2a1 contracts、P2.6B-1、P2.6B-2
以及 ABI v4 全部 PASS。2b scanner 在批处理首次启动时曾以 Windows access violation
退出且无测试输出；未修改代码的独立复核完整执行 35 cases 并 exit 0。该瞬时事件不在
FrameTap 或 Narrow Reconciler 调用链内，但在最终结果中保留记录。

3b-2 的 publish facts、媒体 SHA-256/size/FILE_ID/timestamps 零修改、Scanner
`deleteAllowed=false` / `reconciliationAuthorized=false`、普通 Recording schema 2
以及 Native ABI `0x00040001` / 2856 bytes 均继续由原 65 项和回归门禁证明。
FrameTap blocker 状态为：**FRAME-TAP-BLOCKER-CLOSED-BY-TEST-CONTRACT-FIX**。

## 当前结论

Narrow Reconciler 实现、65 项定向矩阵、P2.6A-3 与全部相关定向回归均已通过；当前
施工现场为 **P2.6C-3B2-NARROW-RECONCILER-READY**。这不是阶段冻结，不包含
P2.6C-4、Recovery UI 或 P2.6D。

## 23. Scanner Fixture UAF Blocker Resolution

批量回归中 `--p2.6c2b-session-inspection` 曾以 Windows access violation
`0xC0000005` 退出。遗留 fixture 已完成 case 29 的生产扫描和分类，但尚未创建
case 30。独立只读诊断确认根因位于 NativeTests helper
`RequireInspectedSession`：它从 `const SessionScanResult&` 返回
`scan.sessions` 内部元素引用，而多个 call site 直接传入
`ScanHistoricalRecordingSessions(...)` 临时值。临时 ScanResult 在完整表达式分号处
析构，随后读取 `session.working.state` 等字段构成 use-after-free。生产
`SessionInspection` 返回自有值对象，未发现对应悬空引用；因此该事件分类为
**TEST FIXTURE DEFECT**，不是 production SessionInspection memory bug。

修复严格限定在 `NativeTests.cpp`：全部 21 个临时 ScanResult call site 改为先保存
具名 `const auto scan`，再在该对象存活期间使用返回引用。helper 同时增加 deleted
`SessionScanResult&&` overload，使未来再次传入临时 ScanResult 在编译期失败，而非
依赖 code review。全文件同型 helper 审计未发现第二个真实风险。原 case 29 现在由
具名 ScanResult 持有结果，case 30 至 case 35 均继续执行，状态为
**CASE29-UAF-CLOSED**。

修复后的 Release x64 clean Rebuild 为 0 warning / 0 error。定向结果：Scanner
35/35 PASS、exit 0、无 access violation；Narrow Reconciler 65/65 PASS、exit 0。
完整相关回归全部 PASS：schema3 consumers 44、3a3 Guard 35、3a2 lifetime owner 32、
3a1 file identity 25、2a2 Path Safety 25、2a1 Inspection Contracts、P2.6B-1、
P2.6B-2、P2.6A-3 Publish 和 ABI v4。P2.6A-3 各场景
`ResidualOutstanding=0`，此前 bounded `PrimeTapGeneration` 合同保持不变。

本修复未修改 production SessionInspection、PathSafety、Manifest reader、
NarrowReconciler、ReconciliationEvidenceGuard、FrameTap、NV12、Encoder、Native ABI
或 Managed API。3b-2 的 strict schema2 `ReadyToPublish` → schema3
`ReconciledCompleted` 唯一转换、零伪造 publish facts、媒体零修改、expected-revision
CAS、幂等和 concurrent-loser 合同继续由 65 项矩阵证明。Scanner fixture blocker
状态为 **SCANNER-TEST-FIXTURE-UAF-CLOSED**，最终门禁恢复为
**P2.6C-3B2-NARROW-RECONCILER-READY**。
