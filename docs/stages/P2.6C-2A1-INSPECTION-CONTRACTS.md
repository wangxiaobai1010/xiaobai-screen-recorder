# P2.6C-2a-1 Inspection Contracts

日期：2026-08-07

分支：`feature/p2.6c-inspection-foundations`

基线：`c0805f4e678117ce6a5041deefb37a6794844066`

## 1. 阶段目标与边界

本切片只建立 P2.6C 只读检查所依赖的三个内部合同：

1. Recording SessionId canonical contract；
2. Recording/Manifest 共用的 OutputRoot resolver；
3. 结构化 Session Manifest ParseResult。

本切片不实现 Scanner、Classifier、Session 目录枚举、handle-based Path Safety、
persistent file identity、live owner、reconciliation、Recovery UI 或 Manifest schema/Native
ABI 扩展。P2.6A 的 Publish/Completed 定义与 P2.6B 的 fail-open Manifest 持久化策略均未改变。

## 2. SessionId 根因

正式 `PreviewEngine::GuidToString` 使用 `StringFromGUID2` 后移除花括号，产生 36 字符
GUID；原 `SessionManifest` validator 却调用 `CLSIDFromString` 并与带花括号文本比较。
P2.6B 测试 fixture 同样使用带花括号 ID，因而掩盖了正式生产形态的不一致。

结果是：正式 `CreateManifest` 在创建 Session 目录之前校验失败；Manifest 持久化按既定
策略 fail-open，Encoder/Finalize/Publish 继续，可能形成成功视频但没有 Session 目录和
`manifest.json`。

## 3. Canonical SessionId 合同

唯一 Writer form 为：

- 36 个 UTF-16 字符；
- 固定 `8-4-4-4-12` GUID 形状；
- 不带 `{}`、不含空白或其他包装；
- 十六进制固定大写，以保持现有生产媒体文件名形态。

`RecordingSessionIdentity` 是唯一 formatter/parser：Writer、Session 目录、Manifest 和媒体
leaf 共享同一身份。Writer 只接受 canonical form；无法格式化时返回空值，使正式 Start
fail-closed，不再产生 `unknown-session`。

Reader/validator 只兼容两种严格外形：bare 36 字符或仅包一层 `{}` 的 38 字符，大小写
可不同。它先解析 GUID value，再重建为大写 bare canonical；不 Trim，不接受额外花括号
或其他 GUID 语法。该兼容只用于 Manifest `sessionId` 字段的只读身份解析；Session 物理
目录与 working/planned 媒体 leaf 必须继续使用 canonical Writer form。带花括号 leaf 是
另一个真实文件名，严格判为 `SemanticInvalid`。身份字段比较基于解析后的 GUID value，
不再比较原始文本。

生产链证据使用共享 formatter 生成 SessionId，通过真实 Native Encoder/Manifest lifecycle
建立 canonical Session 目录和 `manifest.json`，并成功回读终态 Manifest。该证明不依赖
WGC Preview。

## 4. Shared OutputRoot resolver

`RecordingOutputRoot.h/.cpp` 定义内部 `RecordingOutputRootResolution`：

- `status`: `Resolved` / `InvalidInput` / `Failure`；
- 原始 `HRESULT`；
- `mediaOutputRoot`；
- `sessionsRoot`。

正式录制仍按既有固定布局从绝对 diagnostic directory 向上四级，得到
`<artifacts>/p2.5a-recordings`；`sessionsRoot` 唯一等于
`mediaOutputRoot / "sessions"`。resolver 只做词法合同解析，不创建目录，也不宣称路径已
获得安全授权。

`CreateRecordingConfiguration` 使用 resolver 取得媒体根；`SessionManifestStore` 使用同一
resolver 的 managed-root 入口取得 Session 根。Native 中不再散落第二处 `root / "sessions"`
拼接，现有正式 Host 与 LongRun 的媒体保存位置保持不变。中文绝对路径逐字符保留。

## 5. Structured Manifest ParseResult

`SessionManifestStore::ParseManifest` 返回：

| 状态 | 含义 |
| --- | --- |
| `Valid` | schema v1 解码及既有严格语义校验均通过 |
| `NotFound` | 文件或路径不存在 |
| `Inaccessible` | access/sharing/lock/privilege 等不可访问事实 |
| `MalformedJson` | 空文件、非法 UTF-8 或 JSON 语法损坏 |
| `UnsupportedSchema` | JSON/schemaVersion 有效，但版本不受支持 |
| `SemanticInvalid` | schema v1 字段、类型、范围或跨字段不变量无效 |
| `UnknownOrFutureState` | schema v1 中出现未知生命周期状态 |
| `IoFailure` | 其他读取、资源或不可分类 I/O 失败 |

结果同时保留 `diagnosticHResult` 和可用的 `observedSchemaVersion`，分类无需解析错误文字。
只有 `Valid` 才写入调用方 output；所有失败路径保持调用方原值不变。

解析顺序为 JSON 语法 -> schemaVersion probe -> 严格 schema-v1 decode -> 既有 semantic
validation。合法 future schema 即使包含 array/浮点扩展也先得到 `UnsupportedSchema`，不会
误报损坏。已知持久状态字符串 `Unknown` 仍是有效 schema-v1 值；未识别状态单独归类为
`UnknownOrFutureState`。

通用 JSON parser 的对象/数组最大嵌套深度为 128；超限受控归类为 `SemanticInvalid`，
不会由单个小于 1 MiB 的深层 Manifest 触发栈溢出。解析和 semantic validation 中的
`std::bad_alloc` / `E_OUTOFMEMORY` 保留原始诊断并归类为 `IoFailure`，不伪装成坏数据。

原 `LoadManifest` 保留为 compatibility wrapper，并委托同一结构化路径；Writer、Revision
和生命周期调用方没有第二套解析逻辑。旧调用仍获得兼容 HRESULT。

## 6. 定向测试矩阵

`--p2.6c2a1-inspection-contracts` 已通过：

1. 正式大写、无花括号 GUID Writer form；
2. 带花括号 Reader compatibility 并 normalize；
3. 大小写变体按 GUID identity 等价；
4. 非法 GUID、空白、额外包装与错位连字符拒绝；
5. Session 目录使用 canonical form；
6. 正式生产形态 `CreateManifest` 成功，不再 fail-open；
7. 真实 Native Encoder/Manifest lifecycle 建立并回读 Manifest；
8. 普通 OutputRoot 精确路径；
9. 中文 OutputRoot 精确路径；
10. `sessionsRoot` 唯一派生规则；
11. Manifest Writer 使用 shared resolver；
12. 正式媒体输出仍为 `<artifacts>/p2.5a-recordings`；
13. ParseResult `Valid`；
14. 真实不存在文件得到 `NotFound`；
15. 损坏 JSON 得到 `MalformedJson`；
16. 带 array/float 的 future schema 得到 `UnsupportedSchema`；
17. 有效 JSON、无效 schema-v1 语义得到 `SemanticInvalid`；
18. future lifecycle state 得到 `UnknownOrFutureState`；
19. Windows 独占共享阻挡真实得到 `Inaccessible`，受控的生产 HRESULT classifier seam
    独立证明 `IoFailure`。

额外断言覆盖：每个非 `Valid` 结果不改写 sentinel output；resolver 不创建目录；
Manifest Writer 拒绝非 canonical ID；256 层 JSON 安全失败；带花括号媒体 leaf 被拒绝。

## 8. 未实现内容与下一依赖

本切片中的 `EqualPath` 及绝对路径检查仍只是既有 Manifest semantic validation，不是路径
授权证明。没有实现 canonical path authorization、root containment、reparse/symlink/
junction 检查、hard-link defense、handle identity 或 TOCTOU 防护。

这些内容必须由 **P2.6C-2a-2 Path Safety Foundations** 独立实现并通过定向审查；在此
之前不得开始 P2.6C-2b Scanner，也不得把本切片的 resolver 称为 trusted/safe root。

## 9. 阶段结论

三个 Inspection Contracts 已建立并通过生产格式集成证据与 P2.6A/P2.6B/ABI 回归。
P2.6C-2a-1 可进入审查/冻结准备，但本结论不授权 P2.6C-2a-2、Scanner 或 reconciliation。

结论：`P2.6C-2A1-INSPECTION-CONTRACTS-READY`。
