# Security Policy / 安全政策

[中文](#中文) | [English](#english)

## 中文

### 报告安全问题

请勿在普通的公开 GitHub Issue 中发布敏感漏洞详情。

请使用官方仓库的 GitHub 私密漏洞报告功能：`Security` → `Report a vulnerability`。

如果看不到该入口，请勿公开发布利用细节。你可以创建一个内容最少的公开 Issue，仅请求项目提供私密的安全联系渠道；其中不要包含漏洞或利用细节、凭据、个人信息、私人录制内容、令牌或其他机密。

### 报告内容

有帮助的安全报告可以包含：

- 受影响的版本；
- 操作系统版本；
- 简明的复现步骤；
- 预期结果与实际结果；
- 安全影响；
- 在确保安全的前提下提供的概念验证；
- 已移除敏感信息的日志或截图。

### 支持范围

安全修复优先面向最新的官方版本。项目不承诺具体的响应时间或修复时限。

普通 bug 和功能建议请提交到 GitHub Issues；敏感安全报告不应通过普通公开 Issue 提交。

## English

### Reporting a security issue

Do not publish sensitive vulnerability details in a normal public GitHub Issue.

Use GitHub's private vulnerability reporting feature on the official repository: `Security` → `Report a vulnerability`.

If that option is not visible, do not publish exploit details. You may open a minimal public Issue that only asks the project for a private security contact channel; do not include vulnerability or exploit details, credentials, personal information, private recordings, tokens, or other secrets.

### What to include

A useful security report may include:

- the affected version;
- the operating-system version;
- concise reproduction steps;
- the expected and actual result;
- the security impact;
- a proof of concept where safe;
- logs or screenshots with sensitive information removed.

### Supported releases

Security fixes are prioritized for the latest official release. The project does not promise a specific response time or fix deadline.

Ordinary bugs and feature requests belong in GitHub Issues; sensitive security reports do not.
